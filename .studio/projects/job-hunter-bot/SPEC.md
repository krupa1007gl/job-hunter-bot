# «Охотник за вакансиями» (job-hunter-bot) — техническое задание

Версия 0.3 · 2026-10-30 · Статус: draft · Тип: public · Режим студии: lite

## 1. Цель

Публичный Telegram-бот для поиска стажировок, вакансий и фриланс-заказов:
- собирает предложения из разрешённых источников;
- фильтрует их под профиль пользователя и убирает дубли;
- оценивает релевантность **AI-ключом самого пользователя** (модель BYOK, бюджет сервиса на LLM — 0 ₽);
- присылает карточки с кнопками и по кнопке пишет черновик отклика. Отклики бот **никогда не отправляет**.

Без AI-ключа бот тоже работает: оценивает по ключевым словам.

Вторая цель — аккуратный публичный репозиторий для GitHub-портфолио.

**Метрики (через 7 дней):** не меньше 5 полезных предложений в неделю на пользователя; скрыто не больше 50% карточек; от публикации до уведомления не больше 60 минут.

## 2. Объём версии v1 (MVP) и дальнейшие этапы

- **v1 (сейчас):** регистрация и настройки в чате бота; RSS Хабр Карьеры; ручные ссылки; адаптер hh.ru, который ждёт токен; BYOK с шифрованием; запасная оценка по ключевым словам; карточки; черновики откликов; Docker; README.
- **v1.1:** Telegram Mini App для онбординга и настроек; дайджест; избранное; `/sources`.
- **Этап 2:** MCP-коннектор для Claude и ChatGPT. Пользователь ищет работу своим AI на своей подписке, а наш сервис хранит профиль, дедуплицирует, шлёт карточки и готовит отклики. В v1 сервисный слой (профиль, предложения, оценка, черновик) отделяется от Telegram, чтобы коннектор использовал тот же слой без переделки.

## 3. Функциональные требования

Обозначения: «пользователь» — любой зарегистрированный пользователь Telegram; «предложение» — вакансия или заказ.

| ID | Требование | Приоритет | Критерии приёмки |
| --- | --- | --- | --- |
| REQ-001 | Регистрация и согласие | must | 1. `/start` от нового пользователя показывает краткое описание и запрашивает согласие на обработку данных (кнопка «Согласен»). До согласия бот ничего не хранит, кроме Telegram ID и факта отказа или ожидания. 2. После согласия создаётся пользователь, фиксируется время согласия. 3. Вне зарегистрированных пользователей команды не работают, кроме `/start` и `/help`. 4. Есть опциональный режим закрытой беты: allowlist Telegram ID в env; пустой список — бот открыт всем |
| REQ-002 | Профиль | must | 1. Онбординг пошагово спрашивает: тип поиска (стажировка / работа / фриланс, можно несколько), стек, уровень, формат (удалёнка / офис / гибрид), город, мин. зарплата, «о себе» (до 1000 символов). 2. `/profile` показывает профиль, `/profile edit` повторяет онбординг. 3. Неверный ввод — понятная подсказка, профиль не портится |
| REQ-003 | Фильтры | must | 1. `/filters` показывает текущие. 2. Команды: ключевые слова (`/kw add|del`), исключения (`/stop add|del`), мин. зарплата, формат, город, порог балла (0–100, по умолчанию 60). 3. Значения по умолчанию выводятся из профиля |
| REQ-004 | Фильтрация до оценки | must | 1. Исключения, формат, город и зарплата (если указана в предложении) отсекают предложение до любого вызова LLM. 2. Предложение без совпадений по ключевым словам или стеку отсекается. 3. Каждое отсечение пишется с причиной (для отладки), без текста профиля |
| REQ-005 | Сбор из RSS Хабр Карьеры | must | 1. Раз в 30 минут (настраивается) для каждого уникального набора запросов пользователей. 2. Разбор полей title, link, guid, description, pubDate. 3. Не больше 1 запроса в 2 с; User-Agent с URL репозитория. 4. Ошибка источника не роняет бота, пишется в лог и статус |
| REQ-006 | Дедупликация | must | 1. Одно предложение (по нормализованной ссылке или guid) хранится один раз. 2. Пользователь получает карточку одного предложения не больше одного раза |
| REQ-007 | Подключение AI-ключа (BYOK) | must | 1. `/ai` показывает статус: подключено (провайдер, модель, ключ замаскирован `sk-…abcd`) или нет. 2. Подключение: выбор провайдера из списка, ввод ключа; сообщение с ключом бот сразу удаляет из чата. 3. Ключ проверяется тестовым запросом; при ошибке не сохраняется, бот объясняет причину (неверный ключ / провайдер недоступен с сервера / лимит). 4. Ключ хранится только в зашифрованном виде (AES-GCM или Fernet, мастер-ключ в env); в логах, ответах и ошибках не появляется. 5. `/ai off` удаляет ключ |
| REQ-008 | Провайдеры | must | 1. Любой провайдер с OpenAI-совместимым API задаётся пресетом: base_url, модель по умолчанию. 2. Пресеты v1: YandexGPT (Yandex AI Studio), OpenRouter, Groq и «свой» (base_url + модель вручную). 3. Список пресетов — в конфиге, добавление нового провайдера не требует изменения кода |
| REQ-009 | Оценка релевантности | must | 1. С ключом: LLM возвращает JSON `{score: 0–100, reason: до 200 символов}`; ответ вне схемы — одна повторная попытка, затем запасная оценка. 2. Без ключа или при ошибке/лимите: оценка по ключевым словам и стеку (0–100) с пометкой «оценка без AI». 3. Суточный лимит LLM-вызовов на пользователя (по умолчанию 100), чтобы не сжечь бесплатный тариф. 4. Карточка уходит, если балл не ниже порога |
| REQ-010 | Карточка с кнопками | must | 1. Тип и источник, балл, заголовок, компания, зарплата, формат/город, причина, ссылка. 2. Кнопки: «Подробнее», «Черновик отклика», «Скрыть», «В избранное». 3. Не больше 4096 символов. 4. Повторное нажатие не создаёт дублей действий |
| REQ-011 | Черновик отклика | must | 1. По кнопке бот за 2 с отвечает «Пишу черновик…», затем присылает текст по профилю и предложению. 2. Нужен AI-ключ; без него — вежливое предложение подключить `/ai`. 3. В коде нет ни одного метода отправки отклика на площадку |
| REQ-012 | Защита от промпт-инъекций | must | 1. Текст предложения передаётся LLM только как данные в разделителях, с системной инструкцией его не исполнять. 2. Из ответа LLM используется только JSON-схема или текст черновика; команды из него не выполняются. 3. Весь внешний текст экранируется перед отправкой в Telegram (HTML). 4. Тест-фикстура с инъекцией не меняет поведение |
| REQ-013 | Ручное добавление по ссылке | must | 1. Пользователь присылает ссылку на hh.ru, Хабр Карьеру, Kwork или FL.ru. 2. Бот читает одну публичную страницу (если это разрешено robots.txt), извлекает заголовок и текст, оценивает и присылает карточку. 3. Если страница не читается — просит прислать текст вакансии сообщением. 4. Ручные ссылки обходят фильтры и порог |
| REQ-014 | Изоляция и удаление данных | must | 1. Пользователь видит только свои профиль, фильтры, ключ и отметки. 2. `/delete_me` с подтверждением удаляет пользователя, профиль, ключ и отметки. 3. Тест: пользователь A не получает данные пользователя B ни через одну команду или кнопку |
| REQ-015 | Rate limit | must | Не больше 20 команд или нажатий в минуту на пользователя; сверх — короткий ответ «Слишком часто, подожди минуту» |
| REQ-016 | Служебный API | must | 1. `GET /health` → 200 `{"status":"ok"}` при доступной БД, иначе 503. 2. Остальные служебные эндпоинты — только с токеном из env, иначе 401 |
| REQ-017 | Запуск и документация | must | 1. `docker compose up -d` поднимает бота, API и Postgres. 2. `.env.example` без значений, `.env` в `.gitignore`. 3. README: что это, скриншот или пример карточки, архитектура, запуск, как подключить AI-ключ. 4. В CI сканер секретов (gitleaks или аналог) |
| REQ-018 | Адаптер hh.ru по токену | should | 1. Включается, только если в env есть токен приложения hh.ru. 2. Поиск вакансий по запросам пользователей через официальный API, с соблюдением лимитов. 3. Без токена адаптер выключен и не делает запросов |
| REQ-019 | Mini App онбординга и настроек | should (v1.1) | Валидация initData на бэкенде; те же операции, что в чате |
| REQ-020 | Дайджест | should (v1.1) | В 10:00 МСК топ-5 за сутки, если включён |
| REQ-021 | Избранное | should (v1.1) | `/favorites` — до 20 последних |
| REQ-022 | Автосбор фриланс-заказов легальным путём | could | Исследование: поисковые API или grounding у провайдера пользователя. Не реализуется в v1 |

## 4. Нефункциональные требования

- **Производительность.** Ответ на команду или кнопку без LLM — не больше 2 с. Таймаут LLM — 30 с.
- **Надёжность.** Падение адаптера не роняет бота; контейнеры перезапускаются; данные переживают перезапуск.
- **Хранение.** Предложения старше 90 дней (не в избранном) удаляются.
- **Логи.** Структурированные, без ключей, токенов, текста профиля и «о себе».
- **Тесты.** Покрытие не меньше 70% строк для фильтров, дедупликации, оценки, шифрования, адаптеров; тесты не ходят в сеть и в реальный LLM.
- **Объём.** До 500 пользователей и 2000 новых предложений в сутки на одном VPS.

## 5. Бизнес-правила

- BR-1. Бот не отправляет отклики и не авторизуется на площадках от имени пользователя.
- BR-2. Сбор только легальным путём: официальный API, публичный RSS, разрешённая robots.txt страница по ссылке пользователя. Парсинг выдачи hh.ru, Kwork, FL.ru не делаем.
- BR-3. Сервис не платит за LLM: AI работает только на ключе пользователя.
- BR-4. Стек: Python 3.12+, aiogram 3, FastAPI, PostgreSQL, SQLAlchemy 2 + Alembic, Docker, Beget VPS.

## 8. Безопасность и персональные данные

- Секреты (токен бота, мастер-ключ шифрования, пароль БД, токен служебного API, токен hh.ru) — только env.
- Ключи пользователей — только зашифрованы (REQ-007); мастер-ключ не в БД и не в репозитории.
- Изоляция данных пользователей (REQ-014), rate limit (REQ-015), защита от промпт-инъекций (REQ-012).
- **Персональные данные (152-ФЗ, без юридических заключений):** храним Telegram ID, username, профиль и фильтры; согласие при регистрации (REQ-001); удаление по запросу (REQ-014); в README и в `/privacy` — что храним и кому передаём (тексты профиля и вакансий уходят выбранному пользователем AI-провайдеру). Оператор ПД — владелец сервиса. Это риск R5.
- Порт БД не публикуется наружу.

## 10. Допущения

- A1. Mini App переносим в v1.1: регистрация в чате даёт тот же результат быстрее, а модель данных та же.
- A2. Набор пресетов провайдеров достаточен для старта; пользователь сам выбирает провайдера, доступного ему. Мы не гарантируем доступность конкретного провайдера с нашего сервера — это проверяется при подключении ключа.
- A3. Запасная оценка по ключевым словам приемлема по качеству для пользователей без ключа.
- A4. Регистрация приложения на dev.hh.ru — бесплатна (**не подтверждено**); доступ к поиску вакансий может быть не выдан (риск R1).
